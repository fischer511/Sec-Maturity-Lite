1) “Repo spec” za Copilota (prilepi v Copilot Chat kot prvi prompt)
Vloga: Deluješ kot arhitekt in glavni developer. Postavi celoten monorepo in izgeneriraj začetno delujočo kodo.
Cilj produkta – Sec-Maturity Lite:
SaaS orodje za samooceno kibernetske zrelosti (NIS2/ISO 27001 osnove). Organizacije rešijo vprašalnik → izračun stanja (0–5) po domenah → dashboard s trendi po ocenjevanjih → avtomatska priporočila → export PDF. RBAC (Admin, Manager, Viewer), audit log, in “anonymized demo mode”.
Tech stack (obvezno):
•	Backend: FastAPI, Python 3.11, SQLAlchemy, Alembic, PostgreSQL, Pydantic v2, Uvicorn, Auth via JWT (PyJWT), bcrypt.
•	Frontend: React + Vite, TypeScript, Tailwind CSS, shadcn/ui, Zustand (state), Recharts (grafi).
•	PDF export: WeasyPrint ali pdfkit na backendu (server-side).
•	Packaging/Run: Docker Compose (api, web, db, nginx opcijsko).
•	Tests: pytest (backend), Vitest + React Testing Library (frontend).
•	Lint/format: ruff & black (py), eslint & prettier (ts).
Minimalne funkcionalnosti M1 (MVP v 10 dneh):
•	Uporabniki & prijava (JWT), RBAC: Admin, Manager, Viewer.
•	Organizacije (org), ekipe/oddeli (optional v M2).
•	Ocenjevanja (assessments): vprašalnik (20–30 trditev) v 6 domenah (Governance, Asset, Access, Ops/Monitoring, Incident, Business Continuity).
•	Točkovanje: vsaka trditev 0–5 (Likert). Domain score = povprečje; Overall = povprečje domen.
•	Trend: shranjuj vsako ocenjevanje s assessed_at → prikaz “Overall score over time” + “Domain trend”.
•	Priporočila: preprosta rules engine na osnovi praga (npr. če Domain < 3 → seznam top priporočil). Priporočila vzemi iz YAML datoteke.
•	Export: PDF poročilo (organizacija, datum, radar chart domen, bar chart trend, seznam priporočil).
•	Audit log: kdo je ustvaril ocenjevanje, prijave, exporti (tabla v adminu).
•	Demo mode: “Create demo org & sample data” gumb, vse anonimizirano.

Podatkovni model (ustvari SQLAlchemy modele + migracije):
•	User(id, email(unique), password_hash, role[admin|manager|viewer], org_id FK nullable, created_at)
•	Org(id, name, created_at)
•	Assessment(id, org_id FK, created_by FK User, version(int), assessed_at, overall_score(float))
•	AssessmentDomain(id, assessment_id FK, domain(str), score(float))
•	AssessmentAnswer(id, assessment_id FK, domain(str), question_code(str), score(int), note(text?))
•	AuditLog(id, actor_user_id, org_id, action(str), meta(JSON), created_at)
API (FastAPI, verzionirano /api/v1):
•	Auth: POST /auth/login (email, password → JWT), GET /auth/me
•	Users: POST /users (admin), GET /users/me, PATCH /users/me
•	Orgs: POST /orgs (admin), GET /orgs/:id, GET /orgs (admin), PATCH /orgs/:id
•	Assessments:
o	POST /orgs/:org_id/assessments (ustvari osnutek ali končaj)
o	GET /orgs/:org_id/assessments (lista, filter by date)
o	GET /assessments/:id (vse + answers + domains)
o	POST /assessments/:id/answers (bulk upsert Q/A)
o	POST /assessments/:id/finalize (izračunaj domain & overall score, zapiši trend)
o	GET /assessments/:id/pdf (vrne PDF)
•	Recommendations:
o	GET /assessments/:id/recommendations (generiraj iz YAML pravil)
•	Audit:
o	GET /audit (admin), filt: actor, org, action, date
Scoring (services/scoring.py):
•	compute_domain_scores(answers) -> dict[domain->float]
•	compute_overall_score(domain_scores) -> float
•	Vse vrednosti 0–5; zaokroži na 0.1.
Recommendations rules (services/recommendations.py):
•	YAML struktura (primer):
•	governance:
•	  - if: "score < 3"
•	    then:
•	      id: GOV-01
•	      title: "Vzpostavi ISMS jedro"
•	      details: "Politika, vloge, register sredstev, ocena tveganj."
•	access:
•	  - if: "score < 3"
•	    then:
•	      id: ACC-02
•	      title: "Uvedi MFA za kritične sisteme"
•	      details: "MFA za VPN, admin, e-pošto."
•	Enostaven parser: eval samo “score < N” (ne izvajaj poljubnega koda!).

2) Nadaljnji “step-by-step” ukazi za Copilot (po prvem scaffoldu)
A. Dodaj začetni vprašalnik (20–30 vprašanj, 6 domen):
Ustvari datoteko backend/app/services/questions.py z 6 domenami in 20–30 vprašalniki (Likert 0–5). Vprašanja naj bodo kratka, generična, v slovenščini (npr. MFA, patching, backup, incident playbooks, logging). Dodaj helper za pridobitev vprašanj po domeni.
B. Implementiraj scoring in finalize:
Izvedi compute_domain_scores in compute_overall_score. Endpoint POST /assessments/:id/finalize naj prebere answers, izračuna domene in overall, shrani AssessmentDomain zapise in overall_score.
C. YAML priporočila:
Ustvari backend/app/rules/recommendations.yaml z minimalno 2 pravili na domeno (score < 3). Implementiraj services/recommendations.py parser in endpoint za vračanje priporočil.
D. Frontend wizard:
Zgradi /assessments/new wizard: dropdown domena → lista trditev z Likert (0–5), textarea “opomba”, gumbi “Naprej/Nazaj/Shrani osnutek/Končaj oceno”. Po “končaj” kliči finalize endpoint in redirect na /assessments/:id.
E. Dashboard grafi:
Na /dashboard dodaj Recharts LineChart (overall trend po assessed_at) in RadarChart (zadnje ocenjevanje po domenah). Dodaj mini tabelo “zadnja priporočila”.
F. PDF export:
Implementiraj GET /assessments/:id/pdf: server-side generiraj PDF iz Jinja2 template. Za grafe uporabi fallback (tabele + številke); grafične slike lahko dodaš v M2.
G. RBAC & Audit log:
Uveljavi role guard na endpointih (admin ustvarja userje, manager ustvarja ocene, viewer bere). Vsak POST/PUT/DELETE naj pušča AuditLog zapis.
H. Seed skripta:
Ustvari backend/app/utils/seed.py: admin (admin@example.com/Admin!234), demo org, demo user manager, 2 demo ocenjevanji s psevdopodatki.

Funkcionalnosti & navodila (po točkah)
1) Večnivojski vprašalnik (NIS2 mapiranje)
Cilj: podpora level 1..N + parent_question_id za branching.
Koraki:
1.	Dodaj kolone level in parent_question_id v questions.
2.	Endpoints:
o	GET /questionnaires/{id} vrne drevo vprašanj (po domenskih sklopih).
o	POST /assessments ustvari ocenjevanje iz verzije vprašalnika.
o	POST /assessments/{id}/responses sprejme odgovor in vrne naslednja vprašanja glede na branching.
3.	Frontend: komponenta QuestionTree z “stepperjem” in podporo za “drill-down”.
Copilot prompt (backend):
Generate FastAPI models and SQLAlchemy schemas for questionnaires, questions (with parent_question_id, level), assessments, and responses. Provide CRUD endpoints and a GET /questionnaires/{id}/tree that returns questions grouped by domain and nested by parent_question_id.
Copilot prompt (frontend):
Build a React component QuestionTree that renders a multi-level questionnaire with branching. Fetch /questionnaires/:id/tree, show domains as sections, and render child questions when a parent is answered. Persist answers via /assessments/:id/responses.
________________________________________
2) Prilagodljiva teža domen
Koraki:
1.	Tabela weights (po questionnaire_id + domain_id).
2.	Admin UI: sliderji (0–2) po domenah, default 1.0.
3.	Izračun: weighted = raw * domain_weight; total = Σ domain_weighted / Σ domain_weight.
Copilot prompt:
Implement domain weights for scoring. Add weights table and merge weights into the scoring pipeline. Provide an admin endpoint PUT /questionnaires/:id/weights and adjust POST /assessments/:id/score to apply weights.
